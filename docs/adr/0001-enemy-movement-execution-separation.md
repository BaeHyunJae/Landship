# 0001. 적 이동 실행을 플레이어 명령 실행과 분리한다

- 상태: 채택
- 관련: [TASK-46 적 거점과 적 분대](https://app.notion.com/p/408d5512e30a8195828fe306f7b69de9)

## 동기

적 병력은 역할에 따라 이동이 제한된다. 맡은 거점 주변을 지키고, 교전이 끝나면 처음 배치된 위치 주변으로 돌아가고, 정해진 범위 밖으로 쫓아가지 않으며, 주변 아군의 지원 요청에 응한다. 반면 플레이어 명령 실행은 선택 권한과 명령 큐를 지켜야 한다. 적의 자율 이동을 공용 명령 실행에 모드로 추가하면 두 판단 주체가 같은 유닛의 표적과 이동을 동시에 제어하게 되므로, 제어권을 나누는 쪽을 골랐다.

## 결정

적의 역할별 이동 판단과 `AAIController::MoveTo` 호출은 `ULSEnemyBehaviorComponent`(Enemies)가 맡고, 플레이어 명령과 명령 큐는 `ULSOrderComponent`(Controls)가 맡는다. 적 유닛에서는 `ULSOrderComponent`의 Tick을 시작할 때부터 끈다. 적의 자율 이동을 위해 `ULSOrderComponent`에 플레이어 권한을 우회하는 기능이나 외부 제어 모드를 추가하지 않는다.

## 결과

이동 요청 ID, 경로 교체, 공격 대상 접근, 도착 오차 처리의 일부가 두 컴포넌트에 중복된다. 공통 이동 결함을 고칠 때는 두 컴포넌트에 같은 조건이 있는지 대조하고, 적 이동과 플레이어 명령을 함께 검증하는 비용을 받아들인다.

## 검토한 대안

- `ULSOrderComponent`에 적 전용 외부 제어 모드 추가: 플레이어 명령의 권한·상태·표적 획득과 적의 역할 제한을 함께 바꿔야 해서 고르지 않았다.
- 적 전용 AIController와 StateTree·Behavior Tree·EQS 조합: 기존 유닛의 AIController 구성과 에셋 작업이 늘고, 이동 정책을 코드만으로 검증하기 어려워지며, EQS만으로는 경로 전체에 걸친 역할 제한을 풀 수 없어서 지금의 적 역할 범위에서는 고르지 않았다.
- 이동 요청 부분만 작은 공용 헬퍼로 뽑기: 이번에는 기존 패턴을 참고한 별도 실행부를 두고 중복 비용을 받아들였다. 작은 헬퍼를 뽑는 것 자체를 금지한 결정은 아니다.
