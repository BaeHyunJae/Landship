# 0016. 선회 이동 성의 NavMesh 경로에는 엔진 모서리 보정을 적용한다

- 상태: 채택
- 관련: [갈래길 맵과 적 배치안 2개 (TASK-48)](https://app.notion.com/p/408d5512e30a81558018fb980e4a4f52)

## 동기

몸체에 맞는 성 전용 NavMesh의 완전 경로도 모서리의 선분이 실제 성 몸체를 정적 벽에 걸리게 해 이동을 끝내지 못했다. 에이전트 크기·목적지·맵 지형을 바꾸는 대신, 공개 이동과 직접 이동 및 재탐색이 공유하는 경로 기하에 여유를 주는 쪽을 선택한다.

## 결정

`bTurnBeforeForward`를 켠 실제 `ALSCastle`의 완전한 NavMesh 경로에만 엔진의 `OffsetFromCorners`를 50cm 여유로 적용하며, 시작점·목표점과 ADR-0004의 몸체별 Nav 선택 및 ADR-0012의 중심 도착 규칙은 유지한다. 신규 이동 경로, 엔진의 재탐색으로 갱신된 경로, 지뢰 우회 경로 조각은 같은 보정 함수를 사용하고 지뢰 안전성과 경로 비용은 보정된 기하로 판정한다. 일반 병력과 선회 모드를 끈 성은 기존 경로를 유지하며, 재탐색은 새로 생성된 점에 적용해 이전 보정을 누적하지 않는다.

## 결과

경로 점과 길이가 바뀔 수 있으므로 추종과 지뢰 안전성·비용 계산을 같은 보정 경로로 유지해야 한다. 엔진의 포털 반폭 제한과 100점 초과 경로의 보정 생략을 수용하며, 이 보정이 모든 물리 몸체·지형·밀집 상태의 통과를 보장하지는 않는다.

50cm 모서리 보정만으로는 논리 반경 500cm 경로의 투영 끝점과 후방 바위 옆 선분에서 실제 반경 500cm 성의 충돌을 없애지 못했다. 당시 에이전트 크기를 유지한 선택의 동기는 역사로 남기고, 보정을 유지하면서 ADR-0017에서 성 전용 논리 계획 여유와 생성 정밀도를 추가했으며 그 결과 물리적으로 통과 가능한 일부 틈도 경로에서 제외될 수 있다.

## 검토한 대안

- 기존 NavMesh 경로의 모서리 선분을 그대로 추종한다: 완전한 성 전용 경로가 실제 몸체를 정적 코너에 걸리게 하는 관찰된 조건이 남는다.
- 모든 Pawn에 같은 경로 보정을 적용한다: 이번 결함의 범위를 넘어 기존 병력과 선회 모드를 끈 성의 경로 형상까지 바꾸므로 적용하지 않는다.
