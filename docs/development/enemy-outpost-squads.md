# 적 거점·병력 배치와 연결

## 배치

검증 맵은 `/Game/Developers/BHJ/EnemyCombat/L_EnemyCombat`이다. `docs/development/setup-enemy-combat.py`를 에디터 Python으로 실행하면 전용 복사본을 저작한다. 원본 HMH 맵과 병종 표는 이 스크립트가 저장하지 않는다.

검증 맵의 NavMesh는 성의 반경142cm·높이284cm와 기본 해상도(38/19/19cm, 기본 셀19cm)를 사용한다. 초기 폭200cm 거점은 이 조건에서 근접 공격 지점이250cm 밖으로 밀려났다. 현재 적 거점 시제품은 모형과 충돌의 폭·깊이를 함께160cm로 맞춰 기본 셀에서 접근을 확보한다. 높이는200cm이고 아군/적 공용 사거리는250cm다. 상속한 공용 ALSOutpost 자체의 충돌 크기는 바꾸지 않았다. 커스텀 거점의 크기를 바꿀 때는 물리 외곽·NavMesh 에이전트/셀·원점 사거리를 함께 검사해야 한다. 다른 맵의 내비게이션 설정을 이 스크립트가 바꾸지는 않는다.

setup의 참조·수치 유효성 검사는 실제 NavMesh에서의 근접 도달성을 검사하지 않는다. 커스텀 거점의 크기·회전·주변 장애물·높이를 바꾼 뒤에는 공개 지정 공격/공격 이동 프로브에서 실제 피해까지 확인한다. 이 접근 조건에 대한 에디터 자동 경고는 아직 없다.

- `ALSBattlefieldSetup`을 하나 배치하고 `PlayerCastle`, `CoreOutpost`를 명시적으로 지정한다. 성은 아군 진영·성 선택 분류·단일 체력을 가진 액터여야 한다. 기존 `ALSCastle`과 `ALSMobileCastle`을 지원한다.
- 거점은 `ALSEnemyOutpost`를 배치한다. 기본값은 공용 거점 표의 `PrototypeTest` 행을 사용한다. 수치와 무장 여부는 파생 Blueprint 기본값에서 설정한다. `bArmed=false`도 피격 지원 요청은 발생시킨다.
  거점 본체는 공용 시제품 재질의 진영 색으로 표시한다. 최종 거점 아트·규모는 TASK-48이 정하며, 크기를 변경하면 근접 공격 접근을 다시 확인한다.
- 병력은 `ALSEnemyTroop`을 배치한다. 공용 `ALSTroopUnit`의 병종·수치·표시를 사용하며 적 진영으로 시작한다. 병종은 전투 전에 지정한다.
- 병력의 `Behavior`에서 `Role`을 Guard/Assault로 정한다. Guard에는 `GuardedOutpost`를 지정한다. 초기 위치가 복귀 영역의 중심이고, 방어 구역은 거점의 `DefenseRadius`가 정한다.
- 수신 반경·추적 반경·진격 재개 거리·경계 여유·복귀 영역·요청 수명 등은 파생 Blueprint의 Behavior 클래스 기본값에서 편집한다(`EditDefaultsOnly`). 역할·담당 거점은 배치된 인스턴스에서 정한다(`EditInstanceOnly`). 거점의 무장·방어 반경도 파생 Blueprint 기본값이다. 동작 상태·현재 표적·중단 사유를 Blueprint 조회 함수로 확인할 수 있다.

기존 공용 `ALSTroopUnit`, `ALSOutpost`에는 새 판단을 자동으로 붙이지 않는다. 새 적 클래스는 기존 Orders Tick을 끄며, 적 전용 판단과 AI 이동만 활성화한다. 플레이어 명령·아군 자동 교전의 실행 경로는 유지한다.

런타임 배치에서는 SpawnActor의 Transform에 실제 초기 위치를 넣고, 첫 행동 전에 역할·담당 거점을 지정한다. 일반 SpawnActor 직후 참조를 지정할 수 있으며, 구성이 잘못되어 준비 대기 중인 경우도 올바른 참조를 주면 다시 판단을 시작한다. 복귀 기준 위치는 BeginPlay 때의 위치다. 활동 도중 역할·담당 거점을 교체하는 명령 기능은 제공하지 않는다.

## 공통 상태 조회

`ULSBattlefieldStateSubsystem`은 Game/PIE 월드에 있다. `OnWorldBeginPlay`에서 배치된 setup을 해석한다. 참조 해석과 체력 준비 완료는 별개다.

- `IsSetupValid()`는 지정 참조의 구성 검사를 나타낸다.
- `TryGetPlayerCastleState(Out)`는 현재 위치와 생존 상태를 제공한다. 준비 전·조회 실패 시 출력값을 보존한다.
- `GetCoreOutpost()`는 지정한 핵심 거점을 반환한다. 액터가 제거됐다면 null일 수 있다.
- `IsBattleEndedForEnemies()`는 실제로 관찰한 성 사망 또는 기록한 핵심 거점 함락을 나타낸다. 승패의 우선순위나 결과 UI를 결정하지 않는다.

## TASK-49: 함락 소비

`ALSOutpost`는 실제 체력 0의 필수 사망 준비 경로에서 함락을 기록한 뒤 공격·충돌을 정리한다. 맵 해제나 단순 Destroy를 함락으로 바꾸지 않는다.

- 살아 있는 거점 액터에서는 `HasBeenCaptured()`, `TryGetCapture(Out)`를 조회할 수 있다.
- 개별 거점의 `OnOutpostCapturedEvent`는 다음 틱에 한 번 발생한다. 정리 도중 액터가 제거되면 개별 액터 알림은 생략될 수 있다.
- 핵심 거점은 Subsystem의 `TryGetCoreCapture(Out)`로 늦게 연결해도 조회할 수 있다. 스냅샷은 이름·위치·핵심 여부와 약한 액터 참조를 가진다. 참조가 사라져도 기록은 남는다.
- `OnCoreOutpostCapturedEvent`는 정리 스택이 반환된 다음 틱에 한 번 발생한다. 소비자는 먼저 현재 스냅샷을 조회한 뒤 알림을 연결해 초기 연결 시점의 차이를 다룰 수 있다.

이 알림 자체를 승리 UI로 취급하지 않는다. 핵심 함락과 성 사망의 동시 발생, 이미 날아간 투사체, 전역 정지·입력·보상은 TASK-49의 종료 정책에 따른다. 여기서 각 적은 새 이동·공격·지원 처리를 중단하는 종료 대기로 전이한다.

## TASK-45: 위치와 시야

핵심 목표의 정체성과 위치는 setup/Subsystem 조회로 제공한다. 위치 표식은 이 정체성을 사용해야 한다. 거점의 실물·체력 표시를 항상 켜지 않는다. 함락 뒤 위치가 필요하면 보존된 capture 스냅샷을 조회한다.

TASK-45의 시야·미니맵 구현이 현재 작업 브랜치에 통합되어 있다. 전용 맵 빌더는 명시적 전장 경계(-4000/-3500~4000/3500), 바닥 지형 참조, `LSVisionPresentation`, 핵심 거점의 공개 위치 표식을 함께 설정한다. 공개 위치 표식만으로 거점의 실물·체력 선택·공격을 허용하지 않는다.

시야 설정이 있는 맵의 `LSBattlefieldSetup` 에디터 검증은 지정 핵심의 공개 위치 플래그 누락과 다른 액터의 잘못된 공개 플래그를 오류로 보고한다. 핵심을 변경할 때 해당 인스턴스의 플래그도 옮기고 검증한다. 설정을 자동으로 바꾸지는 않는다.

## 지원과 공격 실행 계약

적 행동은 실제 공격 실행·피격 콜백에서 값만 수신함에 넣는다. 그 콜백 안에서 다른 적의 공격·이동을 실행하지 않는다. 실제 새 보고가 없는 한 상대의 원격 현재 위치를 계속 읽지 않는다.

공격 역할은 명시적으로 지정된 플레이어 성에 대한 지원 요청을 별도 조사로 수락하지 않는다. 이미 Subsystem에서 성의 현재 위치를 조회해 진격하므로, 같은 목표의 과거 보고 위치가 진격을 덮어쓰지 않게 한다. 방어 역할과 다른 상대에 대한 지원 요청은 기존 수신·조사 규칙을 따른다.

지원 위치에 도착하면 현재 탐지 범위의 상대를 다시 찾는다. 그 재탐색으로 교전해도 공격 역할의 기존 추적 기준점은 유지한다. 진격 재개 중 성의 공격 위치가 바뀌면 측정한 진행량을 보존하며 경로를 갱신하고, 필요한 거리 또는 실제 성 공격 위치 도달로 회복을 완료한다. 방어 병력의 담당 거점 누락·다른 월드 참조·구역 밖 초기 위치는 에디터 오류와 한 번의 런타임 경고로 드러나며 준비 대기로 남는다.

`ULSBasicAttackComponent::OnAttackExecutedEvent`는 피해 알림과 별개다. 근접은 유효한 타격 시도 커밋 직전, 원거리는 발사 성공 직후 발생하며 피해 0도 실행으로 센다. 명중은 두 번째 실행이 아니다. 약한 참조는 소비 시 다시 검사한다. 이 알림이 실제 피해를 보장하지는 않는다.

`SetAttackTargetResolver`는 준비된 타격 직전에 후보를 조회한다. 콜백은 후보 조회만 하고 이동·공격·지원 실행을 해서는 안 된다. 반환한 대상은 다시 검증하며, null이면 그 타격의 대기시간을 소비하지 않는다. StopAttack은 바인딩을 유지하고 EndPlay는 해제한다. 미바인딩 대상의 기존 동작은 유지한다.

거점 중심은 충돌에 의해 NavMesh에서 제외될 수 있다. 공용 Orders의 지정 공격은 중심이 아닌 사거리 안의 도달 가능한 지점을 사용할 수 있으며, 공격 접근의 도착 오차는 남은 실제 사거리 여유 안으로 제한한다. 조작 권한 검사·표적 우선순위·명령 큐 정책은 바꾸지 않는다. 일반 이동의 도착 오차는 유지한다.

## 이동 경계와 실행부 유지

방어·추적 반경을 조금 벗어나도 `BoundaryAllowance` 안이면 새 추적을 시작하지 않고 안쪽으로 이동한다. 여유 폭까지 넘으면 방어 병력은 복귀 영역으로 돌아가고 공격 병력은 진격 재개 제한에 들어간다. 복귀 도착은 실제 중심이 복귀 영역 안에 있는지로 판정한다.

작은 이탈의 진입·복원 비교에는 `1e-4cm`의 수치 오차를 허용한다. 경계에 놓인 목적지의 부동소수점 오차 때문에 정지한 유닛이 반복 보정에 들어가지 않게 하며, 한계 초과 판정과 `BoundaryAllowance`는 바꾸지 않는다.

일반 진격·복귀·지원 이동에는 RVO 회피를 사용한다. 교전 추격과 탐지 반경 안의 전략 목표를 향한 공격 접근에서는 회피를 끈다. 전략 목표인 성을 추격할 때도 회피를 유지하면 더 빠른 근접병이 도주하는 성과 간격을 유지하며 공격하지 못할 수 있다.

복귀 중 초기 위치에서 `ReturnAreaRadius + 자신의 캡슐 반경` 안으로 접근하면 RVO를 끈다. 엔진의 기본 1.5배 회피 여유가 실제 충돌 검사로 선택한 좁은 대체 지점의 도착을 막기 때문이다. 물리 충돌은 유지하며, 복귀 대기·복귀 차단으로 정지한 수비병은 다른 병력의 회피 대상에 남도록 RVO를 다시 켠다.

적 이동 실행부와 공용 Orders에는 요청 ID 추적, 요청 교체 중 Abort 구분, 사거리 안 공격 지점 탐색, 공격 접근 도착 오차 제한이 중복된다. 적의 이동 구역·복귀·지원 상태를 플레이어 명령 큐와 분리하기 위해 실행부를 별도로 유지한다. 이 중복에는 양쪽 수정과 검증이 필요하다는 유지 비용이 있다. 어느 실행부에서든 공통 이동 결함을 고치면 변경 담당자가 다른 실행부에도 같은 조건이 있는지 확인하고, 적 이동과 공개 플레이어 명령의 실제 맵 검사를 함께 실행한다. 역할·추적 경계 정책은 적 실행부만 소유한다.

## 검증

- `Landship.Enemies.*`: 성 실제 접촉 피해, 전장 참조·수명·함락, 표적 선택과 종료 대기.
- `Landship.Combat.Execution.*`: 실행 알림·재진입·대기시간·실제 타격 시점 표적 조회·투사체 발사/명중 구분.
- 전용 맵을 `-game -LSEnemyCombatTestExit`로 실행하면 실제 NavMesh 이동·교전·복귀·함락 후 중단을 관찰한다. `ENEMY_COMBAT_FINISHED failures=0`을 확인한다. 프로세스 종료 코드만으로 통과를 판정하지 않는다.
- 이 프로브는 복귀 영역 점유/해제, 지원 도착 후 현지 재탐색, 이동하는 성의 회복 경로와 짧은 목표 경로도 검사한다. 실제 통과 근거는 실행 로그이며 프로브 코드의 존재만으로 통과했다고 보지 않는다.
- `-LSEnemyCombatTestExit -LSEnemyMovingSolo`: 더 빠른 근접병이 공개 Move 명령으로 계속 이동하는 성을 추격하여 이동 중 피해를 주는지 확인한다.
- `-LSEnemyCombatTestExit -LSEnemyCoreOrderRunExit -LSEnemyOrderMelee`: 아군 근접병의 공개 지정 공격을 검사한다. `-LSEnemyOrderAttackMove -LSEnemyOrderCorner`를 추가하면 대각선 공격 이동에서 자동 교전·원래 명령 유지를 검사한다.
- `-LSEnemyBoundaryTestExit`는 작은 이탈 보정·한계 초과 복귀·구역 밖 상대의 공격을, `-LSEnemyDenseMarch`는 밀집한 네 병력 모두의 정지 성 타격을 검사한다. `-LSEnemyMovingCastle`은 네 병력의 전진과 근접·원거리 양쪽의 이동 성 타격, 과거 성 지원 위치로의 진격 이탈이 없는지를 검사한다. 좁은 추격열에서 네 병력 모두의 동시 타격을 보장하지 않으며, 병력 간 충돌로 뒤 병력이 막히는 현상은 별도 한계다.
- 일반 플레이에서는 프로브가 스스로 제거되므로 자동 조작을 하지 않는다. 공용 근접 사거리는 CSV와 실제 DataTable에서 Spearman/Cavalry 250cm로 맞췄다.

지원의 추가 자동화는 `Landship.Enemies.Support`다. 실제 공격·피격으로 수신함에 도달하는 요청을 읽어 거리 제한·전담 수비병·병합·만료·치명 피해·피해0·생성 완료 중 제거된 투사체의 지원 부재를 확인한다. 테스트 전용 friend 관찰자는 개발 자동화 빌드에서만 비공개 수신함을 읽는다.

- `-LSEnemySupportTestExit`: 실제 NavMesh에서 거점 우선·가까운 새 요청·현재 지원 유지·보고 위치 갱신과 추적 기준점을 검사한다.
- `-LSEnemyRegressionTestExit -LSEnemyRegressionCase=Detour|Return|Retry`: 구역 밖 우회 경로 거부, 복귀 중 타격·재추적 금지·점유 해제, 실제 경로 중단 뒤 재시도 대기 동안 지원 유지와 재개를 각각 검사한다. `Detour|Return|Retry`는 세 가지 별도 실행값이다.
- `-LSEnemyRegressionLowFPS`는 실제 게임 프레임 간격0.18초 이상을 요구한다. 실행 시 `-ExecCmds="t.MaxFPS 5"`로 자극한다. 경계 프로브에는 `-LSEnemyBoundaryLowFPS`를 사용한다.
- `-LSEnemyCombatTestExit -LSEnemyCoreOrderRunExit -LSEnemyCoreWeaponCapture`: 성의 공격 피해를 검증용으로 거점 현재HP+1로 설정하고 공개 공격 명령을 실행한다. 직접 ApplyDamage로 함락시키지 않으며 실제 무기 타격부터 치명 피해·함락 통지 각1회·정리·적 종료까지 관찰한다. 원래 밸런스로 거점을 파괴하는 데 걸리는 시간을 검증하는 모드는 아니다.

TASK-45와의 시야·미니맵 표식·선택 체력 표시를 별도 체크아웃에서 검사한 과거 근거는 `Saved/Review/TASK-46/seven-check-results.md`에 있다. 현재 작업 브랜치에도 TASK-45가 통합되었으며, 현재 브랜치의 결과는 다시 실행해 확인해야 한다.

현재 프로젝트에서 `docs/development/verify-enemy-vision-pie.py`를 에디터 Python으로 실행하면 두 PIE 월드의 시야·선택·공격·초기화 검사와 DLL 지문·JSON·화면 근거를 `Saved/Review/TASK-46/integrated-branch` 폴더에 기록한다. 화면 가독성은 생성된 화면을 직접 확인해야 한다. 공개 공격 명령 프로브를 시야가 켜진 상태로 검사할 때는 먼저 `docs/development/prepare-enemy-command-map.py`를 실행해 성을 거점에서 1000cm 떨어진 곳으로 임시 배치하고, 실행 인수에 `-LSEnemyRequireVision`을 추가한다. 검증 뒤 `docs/development/setup-enemy-combat.py`를 다시 실행하면 성의 원래 초기 위치(-1800, -1200, 142)를 복원한다. 이 스크립트들의 준비만으로 현재 브랜치의 검증 통과를 의미하지 않는다.
