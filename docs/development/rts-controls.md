# RTS 직접 조종

## HMH 시작

HMH를 실행하면 테스트용 아군 병력 4기, 적 병력 2기, 기존 테스트용 성이 있다. `ALLY TEST`와 `ENEMY TEST`는 입력·명령의 독립 회귀 검사를 위해 테스트 체력을 override한 대역이다. 일반 유닛·성·거점은 PR #12의 공통 체력·진영 코드에 연결되어 있다. 실제 체력·사망·랙돌 검증에는 BHJ의 CombatStats BP와 RealHealthIntegration 검사를 사용한다.

## 조작

- 좌클릭: 성·병력·거점 단일 선택. 적은 정보만 확인한다.
- 좌클릭 드래그: 아군 다중 선택. 병력이 포함되면 성·건물은 제외한다. 판정 기준은 화면에 투영한 액터 중심이다.
- Shift 클릭·드래그: 기존 선택에 대상을 추가하거나 제외한다.
- 더블클릭: 현재 화면 안의 조작 가능한 같은 병종 선택. 기본 병종 구분은 액터 클래스이고, SelectionType으로 별도 지정할 수 있다.
- 지면 우클릭 또는 M 후 지면 클릭: 일반 이동. 이동 중 기본 공격은 중단한다.
- 적 우클릭 또는 A 후 적 클릭: 지정 공격. 사거리 밖이면 접근한 뒤 공격한다.
- A 후 지면 클릭: 공격 이동. 교전이 끝나면 원래 목적지로 이동을 재개한다.
- S: 현재 명령과 예약을 취소하고 정지. 이후 대기 상태에서 적을 자동 탐색하므로 위치 고정이 필요하면 H를 사용한다.
- H: 위치 사수. 이동하지 않고 사거리 안의 적만 공격한다.
- Shift 이동·공격 명령: 기존 명령 뒤에 예약한다. 대상당 최대 64개다. Shift를 누르는 동안 A/M의 목표 입력 대기를 유지할 수 있다.
- Esc 또는 목표 입력 대기 중 우클릭: 목표 입력 취소. 우클릭 취소는 새 이동 명령을 만들지 않는다.
- Ctrl+0~9: 현재 선택한 아군을 부대로 지정. 숫자: 해당 부대 선택. 같은 숫자를 빠르게 두 번 누르면 부대 중심으로 화면 이동.
- Home: 현재 선택 대상들의 중심으로 화면 이동.
- 방향키·가장자리·가운데 버튼 드래그·휠: 기존 RTS 카메라 조작.

좌하단에 선택 수·대표 대상·체력·현재 명령·예약 수를 표시한다. 우하단 M/A/S/H 버튼도 사용할 수 있다. 명령할 수 없는 상태는 버튼을 어둡게 표시한다. 체력 연결이 없는 대상은 임의 수치를 표시하지 않고 `HP: --`로 표시한다. HUD 패널이나 실제 위젯 위 클릭은 전장으로 전달하지 않는다.

다중 이동은 충돌 반경을 고려한 격자 대형으로 목적지를 분산한다. 이는 기본 목적지 배정이며 스타2 수준의 군집 이동·병목 통과·대형 유지 알고리즘을 구현한 것은 아니다.

## 구현 경계

- `ULSSelectableComponent`: 선택 가능 여부, 병력/성/건물 분류, 조작 권한, 병종 식별.
- `ALSPlayerController`: 선택 입력, 명령 해석, 부대 지정, 대상별 목적지 배정.
- `ULSOrderComponent`: 이동/지정 공격/공격 이동/대기/위치 사수 상태와 예약 명령 실행.
- `ULSBasicAttackComponent`: 공격 간격과 피해 적용. 자동 모드에서도 현재 유효한 공격 대상을 유지한다.
- `ALSRTSHUD`: 선택 원·체력바·입력 대기 상태와 명령 버튼. 최종 UI 아트는 별도다.

일반 이동 명령은 경로를 사전 검사하고, 유효하지 않으면 기존 명령을 교체하지 않는다. 예약 명령은 실행 시 다시 검사하여 사망한 목표 등 무효 명령을 건너뛴다. 이동 도중 새 장애물 등으로 경로가 실패하면 해당 명령을 종료하고 다음 예약으로 진행한다.

지정 공격은 수동 지정 대상을 우선하며 대상이 사망하면 끝난다. 대기·공격 이동은 감지 범위 안에서 자동 탐색하고, 유효한 현재 대상을 유지한다. 위치 사수의 탐색 범위는 공격 사거리다. 유닛 감지 범위는 기존 DataTable 행을 사용한다.

현재 성에는 독립적인 공격 무장을 추가하지 않았다. 따라서 기본 성은 선택·이동·정지·위치 사수·부대 지정이 가능하고, 기본 공격 컴포넌트가 없는 성의 공격 명령은 거부한다. 정적인 거점은 이동할 수 없다.

## 팀원의 진영·체력 기능 연결

`ILSBasicAttackParticipant`의 생존·피해 허용·피해 적용 계약은 기존 문서 `basic-attack-component.md`를 따른다. 체력 UI를 위해 `GetCombatHealth(Current, Maximum)`을 추가했다. 체력 기능에서 조회만 하고, UI에서 체력을 변경하지 않는다.

`ULSSelectableComponent::SetPlayerControlled`는 각 액터의 BeginPlay에서 준비된 공통 진영을 사용해 설정한다. Ally는 조작 가능하고 Enemy는 정보 조회만 허용한다. 이는 진영 자체를 새로 정의한 값이 아니다. 플레이 중 진영 변경 잠금은 팀원 구현을 유지한다. 공격 가능 여부는 별도로 대상의 CanReceiveBasicAttack에서 실제 진영 규칙을 검사한다.

유닛의 클릭 광선은 Visibility를 사용한다. 기본 Pawn 프로필의 Visibility 무시를 덮어써 유닛 캡슐이 클릭을 막도록 설정했다. 별도 Blueprint에서 충돌 프로필을 재정의하면 이 응답도 유지해야 한다.

## 자동 검증

`Landship` 자동 검사 16개가 통과했다. 선택·부대·명령·실제 유닛 BP의 클릭 충돌 회귀 검사를 포함한다. HMH 연속 동작 검사 37개도 통과했다. 일반 이동 중 공격 억제, 장애물 우회와 경유지, 추적 공격, 이동 명령으로 공격 취소, 위치 사수, 적 처치 후 원래 목적지 및 예약 목적지 이동을 검사한다.

실제 실행 화면에서는 빠른 드래그로 4기 선택, 같은 병종 더블클릭, 적 정보 전용 선택, 선택 원·체력바, A 지면 클릭 공격 이동, HUD H 버튼, Ctrl+1 지정 후 적을 선택했다가 1로 4기 복원을 확인했다. Shift 추가·제외와 예약은 로직 및 맵 검사로 확인했으며 모든 물리 키 조합의 UI 검증을 마친 것은 아니다.

빠른 드래그는 InputKey 수신 시 시작 위치를 저장해 프레임 처리 지연에 영향을 받지 않게 했다. 숫자 부대 지정은 이벤트 수신 시 Ctrl 상태를 읽어 짧은 조합 키 입력을 처리한다. 진단이 필요하면 콘솔 변수 `LS.RTS.InputDebug 1`을 사용한다. 기본값은 0이다.

실제 맵 이동은 HMH 실행 옵션 `-HMHRTSTestExit`로 재현한다. `HMH_RTS_FINISHED failures=0`이 성공 기준이다.

```powershell
& 'C:/Program Files/Epic Games/UE_5.8/Engine/Binaries/Win64/UnrealEditor-Cmd.exe' 'C:/Report/Projects/LandShip/Landship.uproject' /Game/Developers/Minhyeok/HMH -game -unattended -nop4 -nosound -NullRHI -HMHRTSTestExit '-abslog=C:/Report/Projects/LandShip/Saved/Logs/HMHRTSRuntime.log'
```

HMH의 테스트 액터가 없으면 에디터를 닫고 `setup-hmh-rts-controls.py`를 Unreal Python commandlet에서 실행한다. 같은 이름의 기존 액터는 재사용하고 삭제하지 않는다. 네비게이션과 바닥 채널은 기존 HMH 이동 테스트 환경을 사용한다.

HMH 조작용 병력의 체력은 테스트 대역이며 일반 전투 대상의 체력·진영은 공통 구현에 연결되어 있다. 안개·시야 제한·네트워크 권한 검사·투사체·애니메이션 타격 시점·지형 고저차 전투 규칙은 이번 범위에 포함하지 않는다. Shift 조합을 포함한 모든 입력 조합을 모든 해상도에서 검증한 것은 아니다.


## 이동 및 명령 회귀 검증

이동·공격 이동 명령은 NavMesh에 보정한 목적지를 저장한다. 이미 보정 목적지에 도착한 경우도 유효한 요청으로 처리한다. 명령 컴포넌트는 성의 개별 이동 진입점을 다시 호출하지 않고 AIController의 경로 추적 결과를 사용한다.

이동 종료는 경로 추적의 완료 이벤트로 판단한다. 성공과 실패·외부 중단을 구분하며, 이전 요청 ID의 이벤트는 새 명령에 반영하지 않는다. 실패·중단된 명령은 종료하고 유효한 예약 명령을 이어서 시도한다. 컴포넌트 종료 시 완료 구독을 해제한다.

다중 명령은 명령 종류를 실행할 수 있는 대상만 먼저 추린 뒤 대형 목적지를 계산한다. 이동 불가능한 건물은 이동 대형의 인원 수와 간격 계산에서 제외된다. HUD 버튼도 같은 명령 종류별 능력 검사를 사용한다. 이동 목적지 표시는 디버그 드로잉 대신 HUD 투영 표시를 사용한다.

검증 기록: Win64 Development Editor 빌드 성공, Landship 자동 테스트 16개 통과, HMH 검사 37개 통과. 신규 HMH 검사는 건물 혼합 선택, 외부 이동 중단, NavMesh 경계 보정과 AlreadyAtGoal, 이전 요청 ID의 완료 통지, Blocked 처리 경로를 포함한다. Blocked는 경로 추적 컴포넌트에 실패 결과를 주입한 검사이며 실제 장애물에 장시간 갇히는 상황을 재현한 것은 아니다.

- 자동 테스트 결과: `Saved/Automation/RTSRefactorVerified/index.json`
- HMH 실행 로그: `Saved/Logs/HMHRTSRefactorVerified.log`
- 성공 기준: `HMH_RTS_FINISHED failures=0`

이번 검증은 NullRHI 실행을 포함한다. HUD의 새 목적지 표시를 실제 렌더링 및 Shipping 패키지에서 검증한 것은 아니다. HUD의 UUserWidget/WBP 이전, 선택·부대 관리의 별도 클래스 분리, 선택 등록부 및 탐색 주기 최적화, 테스트 지원 모듈의 배포 분리는 아직 적용하지 않았다.


## 공통 체력·진영 병합

병합 원본은 `origin/prototype`의 PR #12이다. `ULSHealthComponent`, 진영 인터페이스, 표적 라이브러리, 피해 결과, 개발 설정, 필수 사망 훅, 랙돌 및 제거 정책은 팀원 구현을 유지한다. BHJ의 테스트 맵과 신규 인간형 BP도 원본을 사용한다.

우리 공격 인터페이스는 공통 구현을 조회·호출하는 어댑터이며 체력이나 진영을 중복 소유하지 않는다. 체력 초기화에 성공한 유닛·거점에만 공격 수치를 연결하고, 실패 상태에서 이동을 복구하지 않는다. 사망 필수 처리에서 기본 공격 타이머를 중단한다. 선택·명령·HUD는 동일한 공통 체력 상태를 읽는다.

이 통합은 즉시 기본 공격 방식이다. 투사체에 의한 지연 피해는 구현하지 않았으며, 향후 발사 시 MakeDamageRequest로 요청을 생성하고 명중 시 전달해야 한다. HMH의 기존 테스트 대역을 실제 진영·체력 구현의 증거로 간주하지 않는다.

최종 통합 검증에서 Landship 자동 테스트 31개와 HMH 조작 검사 37개가 통과했다. 자동 테스트 결과는 `Saved/Automation/HealthMergeVerified/index.json`, 로그는 `Saved/Logs/HealthMergeVerifiedTests.log`와 `Saved/Logs/HMHHealthMergeFinal.log`에 기록했다. NullRHI 검증이며 팀원 PC 및 실제 랙돌 렌더링 확인은 별도다.

HMH의 종료 시 내비게이션 CleanUp 오류 로그는 병합 전 `HMHRTSRefactorVerified.log`에도 존재한다. 이번 병합으로 새로 발생한 오류는 아니며, 검사 통과와 별도로 남아 있는 종료 정리 문제다.
