# 전투 HUD와 명령 카드 261101

## 화면과 선택 규칙

`/Game/Landship/HUD/UI/WBP_BattleHUD`가 선택 정보, 명령 격자와 발견 알림의 디자인을 소유한다. `ULSBattleHUDWidget`은 데이터를 표시하고 요청만 전달한다. 비용, 인구수, 쿨타임은 UI가 변경하지 않는다.

우측 하단은 5열 3행의 고정 격자다. 셀 번호는 왼쪽 위부터 0~14다. 빈 셀도 자리를 유지한다.

- 첫 줄 0~3: 이동 M, 정지 S, 공격 A, 위치 사수 H. 4번은 예약된 빈 칸이다. 실행 가능한 공통 명령은 선택된 아군 전체에 전달한다. 성은 기본 공격이 없어 공격 칸이 비활성화된다.
- 성의 둘째 줄 5~7: 일반 대포 Q, 산탄 W, 발리스타 E. 기존 조준과 확인 시전 기능을 사용한다.
- 성의 셋째 줄 10~12: 창병 F1, 궁병 F2, 기마병 F3 생산. 기존 생산 요청과 독립 쿨타임을 사용한다.
- 일반 병력은 공통 명령을 표시한다. 별도 스킬이 없는 셀은 빈 상태다.
- 여러 병종을 선택하면 `SelectionType`으로 묶은 활성 병종의 전용 명령만 표시한다. 현재 병종이 선택에 남아 있으면 유지하고, 그렇지 않으면 첫 조작 가능 대상을 기준으로 한다. Tab은 선택을 유지하면서 활성 병종만 순환하고 진행 중인 조준을 취소한다.
- 특수 명령 한 번은 활성 병종 중 첫 실행 가능 제공자 한 개가 실행한다. 여러 유닛의 스킬을 한 번에 모두 사용하지 않는다. 공통 이동·공격 등은 전체 선택에 적용한다.
- 선택 없음 또는 적 정보 확인 상태에서는 실행 가능한 명령이 없다. 다른 선택의 오래된 버튼 요청은 재검사하여 거부한다.

`ULSSelectableComponent::CommandGroupName`으로 화면에 표시할 병종 이름을 지정한다. 선택 상세 수치는 기존과 같이 첫 대상을 기준으로 하며, 명령 카드 제목은 활성 병종을 표시한다.

승패 판정이 활성화된 전투에서 결과가 확정되면 명령 격자 전체를 비활성화하고 채워진 칸에 '전투 종료'를 표시한다. 버튼·단축키 실행과 Tab 병종 전환을 막고, 쿨타임·병종 전환 안내와 발견 알림을 숨긴다. 셀의 제목·레벨과 고정 15칸 배치는 유지한다.

## 다른 유닛의 스킬 추가

`ULSCommandProviderComponent`의 Blueprint 또는 C++ 파생 컴포넌트를 해당 유닛에 부착한다. UI에 병종 분기나 버튼을 추가할 필요가 없다. 성은 `ULSCastleCommandProviderComponent`를 기본 컴포넌트로 가진다.

1. `GetCommands(Controller)`에서 안정적인 명령 ID, 제목, 셀 5~14, 단축키, 설명, 레벨, 활성 여부, 남은 쿨타임과 전체 쿨타임을 반환한다. 상태 조회는 자원 소모나 상태 변경 없이 수행한다.
2. `ExecuteCommand(Id, Controller)`에서 소유권, 생존, 실행 가능 상태, 자원과 쿨타임을 다시 검사하고 실제 기능을 호출한다. 성공한 요청만 true를 반환한다. UI의 활성 상태를 실행 권한으로 신뢰하지 않는다.
3. 즉시 실행형 스킬은 여기서 실행한다. 대상 지정형은 기존 성 무장처럼 해당 기능의 조준 상태로 진입하고, 대상 확인 시 비용과 쿨타임을 확정한다. 새 유닛용 범용 조준·범위 표시 시스템이나 신규 전투 스킬 자체를 이번 작업에서 추가한 것은 아니다.

한 유닛에 제공자를 여러 개 부착할 수 있다. 동일 유닛의 중복 셀·ID, 셀 간 단축키 중복, 공통 명령과 예약 입력 충돌은 해당 명령을 비활성화하고 '설정 충돌'로 표시한다. 범위 밖 셀, 빈 ID·제목, 음수 또는 유한하지 않은 쿨타임은 표시하지 않는다. 같은 병종의 같은 셀은 동일한 제공자 클래스·ID·단축키를 사용해야 한다.

예약 입력은 공통 명령 M/S/A/H, Tab, Esc, Home, 방향키, 숫자 부대 키, 보조 키 자체, 마우스·게임패드·축 입력이다. Shift·Ctrl 조합 스킬은 지원하지 않는다. 단축키와 버튼은 `ULSCommandCardComponent::ExecuteCell`의 같은 재검사 경로를 사용한다.

## 디자인 편집과 화면 배치

명령 카드의 제목·키·레벨·상태는 서로 다른 텍스트 위젯이다. 레벨이 없으면 해당 줄은 비운다. 남은 시간과 진행 막대를 함께 표시하며 성 무장 막대의 분모는 발사 시 확정한 쿨타임을 사용한다.

명령 카드 기준 크기는 420×336, 선택 정보는 340×125다. `FLSBattlefieldHUDLayout`이 미니맵·정보·명령 카드를 비례 축소하여 화면 안에 배치한다. 미니맵이 없어도 같은 규칙을 사용한다. `ALSRTSHUD::GetCommandCellRect`는 네이티브 클릭 경로와 맵 검사에서 같은 격자 위치를 사용한다. 최종 아트·배치는 WBP 디자이너에서 조정하되 이름이 지정된 위젯 연결을 유지한다.

첫 생성 도구는 `docs/development/setup-battle-hud.py`다. 기존 WBP를 덮어쓰지 않는다. 이번 변경에서는 이전 작업 중 생성한 미추적 WBP만 백업 후 새 격자로 다시 생성했다. 생성기는 Editor 전용 모듈을 사용하며 저장 가능한 `/Engine/EngineFonts/Roboto` 폰트 에셋을 참조한다.

루트는 SelfHitTestInvisible이며 패널 클릭은 전장 선택·명령으로 전달하지 않는다. 패널 위의 키보드 입력은 기존 Slate 경로를 통해 허용한다. 최초 적 발견 알림은 실제 Paint 후에만 표시 완료를 기록하고 기본 3초 뒤 숨긴다.

## 확인 범위

`Landship.HUD.BattleWidget.StatesAndRequests`는 저장된 WBP의 15개 셀, 성 무장 조준·쿨타임·잠금, 병력 선택 전환, 일반 유닛의 시험 제공자 실행, 버튼·단축키 공통 경로, 혼합 선택의 Tab 전환, 오래된 클릭·제공자 제거·중복 설정 차단을 검사한다. 시험 제공자는 실제 게임 병력에 부착하지 않는다.

`HMHCastleWeaponsTestExit`는 실제 HMH 맵에서 성 무장·생산, 산탄 이후 재이동과 명령 카드 전환을 확인하고 `Shot ShowUI`로 UMG를 포함한 화면을 저장한다. 일반 고해상도 장면 캡처에는 UMG가 제외되므로 HUD 검증에는 사용하지 않는다.

앱 직접 조작 권한이 없어 OS 마우스 클릭·창 전환·다른 Windows 배율 조합은 수동으로 재검증하지 못했다. 위젯 이벤트 검사와 렌더링 캡처를 이 수동 확인의 대체로 간주하지 않는다. Shipping·모바일 터치 입력·최종 아이콘 아트는 이번 작업 범위 밖이다.

## 검증 결과

전체 자동 검사 `Saved/Automation/CommandGridFinal/index.json`은 성공 94, 기존 경고 포함 성공 1, 실패 0이다. 이후 예약 단축키 차단을 보완하고 HUD 계약 검사를 다시 실행하여 성공했다(`Saved/Automation/CommandGridReservedKeys/index.json`).

실제 맵 검사 `Saved/Logs/CommandGridCompleteWeapons.log`는 44개 조건 통과, 실패 0이다. `Saved/Screenshots/WindowsEditor/ScreenShot00029.png`는 병력 선택, `ScreenShot00030.png`는 혼합 선택에서 성 카드로 전환한 화면이다. 성의 무장·생산은 기존 컨트롤러가 선택한 첫 성을 기준으로 하며, 여러 성의 개별 생산 대기열은 이번 작업에 포함하지 않았다.
