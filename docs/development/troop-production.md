# 병력 생산

아군 성을 선택한 상태에서 F1 창병, F2 궁병, F3 기마병 또는 우측 하단 버튼으로 즉시 생산한다. 병력과 성을 함께 선택한 경우에도 생산할 수 있다. 여러 아군 성을 선택하면 선택 목록의 첫 성을 생산 위치로 사용한다. 성 미선택·적 성 선택·성 파괴 상태에서는 생산하지 않는다. 기존 이동·공격 설명과 M/A/S/H 명령 버튼은 화면에서 제거했으며 해당 단축키 기능은 유지한다.

## 쿨타임과 인구수

병종별 쿨타임은 각각 10초다. 다른 병종은 독립적으로 생산할 수 있다. 쿨타임은 플레이어의 `ULSTroopProductionComponent`가 관리하므로 성을 바꾸거나 선택을 해제해도 초기화되지 않는다. R은 할당하지 않았다. 자원 비용이나 생산 예약 큐는 없다.

공통 `ALSGameState`의 인구수를 사용하며 `ALSGameMode`가 상한을 100으로 설정한다. 맵 시작 시 살아 있는 아군 병력 `ALSUnit`을 집계하고 이후 이 생산 기능으로 생성한 병력을 등록한다. 성과 적은 인구수를 차지하지 않는다. 병종에 관계없이 한 기당 1을 사용하고, 사망 시 반환한다. 시체 제거 때 다시 반환하지 않으며 살아 있는 병력을 직접 제거해도 반환한다. 다른 시스템에서 임의로 런타임 생성한 병력의 자동 등록은 포함하지 않는다.

## 생성 위치

성·병력의 충돌 반경을 고려해 가까운 원부터 바깥 원으로 탐색한다. NavMesh 위의 공간인지, 충돌 형상이 겹치지 않는지, 성 위치에서 연결되는 경로인지 확인한다. 보행 병력은 반경 42cm, 기마병은 65cm 기준이다. 기본 최대 탐색 거리는 5000cm이며 생산 컴포넌트에서 변경할 수 있다. 전체 탐색 범위에 빈 공간이 없으면 실패 이유를 표시하고 인구수·쿨타임을 소모하지 않는다.

생성은 지연 생성으로 병종·진영을 먼저 지정한 뒤 완료한다. 생성이나 초기화가 실패하면 인구수 예약을 반환한다. 쿨타임은 성공한 경우에만 시작한다. 중복 요청은 처리 중 잠금과 쿨타임으로 차단한다.

## UI와 입력

우측 하단에 세 생산 버튼, 남은 쿨타임, 진행 막대, 현재 인구수와 상한을 표시한다. 아군 성 미선택·생산 제한 상태에서는 버튼을 비활성 색으로 표시한다. UI 클릭은 전장 선택으로 전파하지 않는다. 버튼 클릭과 F1/F2/F3는 `ALSPlayerController::ProduceTroop`를 통해 같은 생산 기능을 호출한다. UI는 인구수나 쿨타임을 별도로 변경하지 않는다.

## 검증

Editor 빌드와 전체 Landship 자동 테스트 38개가 통과했다. `HMH_TroopTypes`의 `-HMHProductionTestExit`는 실제 버튼 클릭·세 병종 생성·성 선택 조건·먼 빈 공간 탐색·독립 쿨타임·인구수 상한·사망/제거 중복 반환 방지·공간 부족 실패와 재시도를 검사한다. 일반 플레이에서는 해당 검증 액터를 제거하며 쿠킹 제외 대상으로 지정한다.

- 자동 테스트: `Saved/Automation/TroopProductionFinal/index.json`
- 생산 실행 검사: `Saved/Logs/HMHTroopProductionFinal.log`
- 기존 이동·전투 회귀 검사: `Saved/Logs/HMHTroopProductionRegression.log`

키보드 단축키 경로는 코드로 확인했으며 위 실행 검사는 버튼의 클릭 처리 함수를 호출하는 방식이다. OS 키보드 입력·다른 해상도·Shipping 패키지는 별도로 확인해야 한다. 기존 내비게이션 종료 시 CleanUp 오류는 남아 있다.
