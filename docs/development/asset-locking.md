# 에셋 잠금

<!-- 작성 규칙은 CONTRIBUTING.md의 '문서' 절을 따른다. -->

## 언제 쓰는가

`Content/` 아래 파일(`.uasset`, `.umap` 등)을 고치기 전에 쓴다. 이 파일들은 병합할 수 없어서, 두 사람이 같은 파일을 동시에 고치면 한쪽 작업을 버려야 한다. 잠근 파일은 잠근 사람만 고칠 수 있고, 다른 사람의 작업 공간에서는 읽기 전용이다.

## 준비

- Git LFS를 설치하고 `git lfs install`을 한 번 실행한다.
- 저장소를 최신 상태로 받는다. `.gitattributes`에서 `Content/` 아래 파일이 잠금 대상(`lockable`)으로 지정되어 있어, 받은 파일은 읽기 전용이 된다.

## 순서

1. `git lfs locks`로 고칠 파일을 다른 사람이 잠갔는지 확인한다. 잠겨 있으면 잠근 사람에게 언제 풀지 묻는다.
2. `git lfs lock <파일 경로>`로 고칠 파일을 잠근다. 경로는 저장소 루트 기준이다. 예: `git lfs lock Content/Landship/Castle/BP_Castle.uasset`
3. 파일을 고치고 커밋해 PR을 올린다.
4. PR이 병합되면 `git lfs unlock <파일 경로>`로 잠금을 푼다. 고치지 않기로 했으면 그때 바로 푼다.

- 읽기 전용 파일을 탐색기나 에디터에서 강제로 쓰기 가능으로 바꾸지 않는다. 잠그지 않고 고친 변경은 같은 파일을 잠근 사람의 작업과 충돌한다.
- 다른 사람의 잠금을 `--force`로 풀지 않는다. 풀어야 하면 잠근 사람에게 먼저 묻는다.

## 성공 확인

- 잠근 뒤 `git lfs locks`에 그 파일이 내 이름으로 표시된다.
- 잠금을 푼 뒤 `git lfs locks`에서 그 파일이 사라진다.
