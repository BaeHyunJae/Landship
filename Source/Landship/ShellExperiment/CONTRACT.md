# 포탄 조합 실험 계약

## 제공하는 것

### 규칙과 기능 단계

- 기존 `L_ShellExperiment`는 `Legacy`, 별도 `L_ShellSupplyExperiment`는 `SupplyStageOne` 규칙을 사용한다. 개선 규칙을 추가해도 기존 맵·위젯·데이터와 모듈의 직렬화 값을 바꾸지 않는다.
- `SupplyStage`는 선택 가능한 기능을 구분한다. `Physics`는 폭발·추진, `Charge`와 `Transport`는 여기에 전격, `Materials`는 중력·철구를 더한다. `Complete`는 접착·냉각·분열을 포함한 여덟 모듈을 제공한다. 분열은 이 단계에서도 Heavy 격파 전에는 선택할 수 없다. 코드가 지원하는 단계와 맵에 실제 저작한 단계는 구별하며, 기존 맵을 자동으로 최종 배치로 간주하지 않는다.
- 초기 선택지·순서는 `AvailableModules`, `InitialFirst`, `InitialSecond`로 정한다. 단계와 선택지가 다르거나 두 슬롯이 같으면 구성 오류로 중단한다. 발사 때 규칙·조합·수치·피해 출처와 자원 예산을 값으로 고정하고, 명중 때 실제 접점·법선·입사 방향을 기록한다.
- 개선 규칙은 기존 난수 사건을 끈다. 보급·공성은 아래의 명시적 일정과 전용 제어를 사용한다. 공통 체력·진영·피해·거점 함락·프레임 말미 승패 판정은 그대로 사용한다.

### 몸체·충격·후행 대상

- `ULSShellReactiveComponent`는 권위 있는 물리 primitive 하나와 `BodyId`·세대를 보유한다. 물리적 존재와 공통 체력상 생존은 별개다. 같은 primitive를 재지정하면 식별값·전하·연속 접촉을 유지한다. 일반 몸체 교체·제거는 전하와 양쪽 접촉 관계를 정리한다. 사망 전환처럼 같은 실체를 이어야 하는 교체는 조정자의 명시적 이전 경로로 처리한다.
- 명시적 이전은 기존 `BodyId`와 잔여 전하·출처를 새 몸체에 한 번 옮기고 세대를 갱신한다. 새 형상에 실제로 계속 닿는 접촉만 같은 접촉 식별값으로 잇고, 유효한 접착 부위와 예약된 몸체 대상도 갱신한다. 큐에 담은 접촉도 원본 Actor의 약한 참조에만 기대지 않고 몸체 식별값과 실제 연속 접촉 식별값으로 현재 몸체에서 재검증한다. 분리·제거되어 연속성이 끊긴 사건을 새 몸체에 재생하지 않는다. 사망 준비가 이동을 정리하기 전에 보관한 물리 상태와 출처·진영 값을 이전하며, 제거된 원본 대신 기본 진영을 새로 부여하지 않는다. 원본과 대체 몸체에 자원이나 충격을 중복 적용하거나 새 체력 풀·공격 권한을 만들지 않는다.
- 충격은 kg·cm/s이며 실제 솔버 질량 또는 Character 이동 질량으로 속도 변화를 구한다. 기존 `Mass`는 Legacy의 무차원 수치다. 강체 충돌에 스크립트 밀어내기를 중복 적용하지 않는다. 접촉 속도는 프레임의 PrePhysics 선속도·각속도 표본으로 구하며 서브스텝의 정확한 순간 속도는 보장하지 않는다.
- 추진은 발사 때 기록한 입사 방향의 XY 성분으로 몸체 하나를 수평으로 민다. 수평 방향이 없으면 실패하고 임의 방향을 대신 고르지 않는다. 추진 선행 포탄은 직격 체력 피해를 주지 않지만 직격 충격·이후 물체 충돌·후행 모듈은 각 규칙대로 처리한다.
- Arena 설정을 끈 규칙에서 모듈 폭발은 거리 감쇠와 총운동량 예산을 나눠 수직 상향 충격을 준다. 환경 기폭은 방사형 방향과 상향 비율을 유지한다. `ModuleMaximumDeltaSpeed`는 기존 속도에 더하는 모듈 변화량을 제한한다. 초과 몫은 다른 몸체에 재분배하지 않는다. 직격 충격과 환경 기폭은 이 모듈 상한의 대상이 아니다.
- 폭발의 대상·노출·충격은 피해 전 고정하고, 피해와 사망 전환 뒤 남는 현재 몸체에 한 번 적용한다. 실제 현재 형상으로 차폐하며 기폭체 자신만 방출 몸체로 구별한다. 표면 폭발의 피격 몸체는 다른 대상을 가릴 수 있다. 생존자 최소 속도 보정은 Legacy에만 적용한다.
- Arena 설정을 끈 규칙에서 몸체 대상 후행 효과는 식별값·세대와 로컬 접점·법선을 따른다. 전격·접착·냉각의 대상이 제거되면 예약을 취소하고 주변 몸체를 대신 고르지 않는다. 후행 추진은 대상이 없거나 제거되면 예약·Space 발동을 유지하고 **최초 착탄점**에서 `ThrustRadius` 안의 실제 표면 거리·차폐로 범위 추진을 실행한다. 모든 대상의 방향은 원래 발사의 XY 방향이며 예산을 거리 가중치로 나누고 몸체별 상한을 적용한다. 빈 범위도 발동 표현을 실행한다. 유효하지만 움직일 수 없는 몸체는 단일 추진의 실패 규칙을 유지한다. 위치 기반 후행 폭발은 마지막 유효 위치를 사용한다.
- Arena 설정을 끈 규칙에서 중력장은 월드 위치에 고정되며 피격 몸체를 따라가지 않는다. 실제 표면 거리·차폐로 이동 가능한 살아 있는 몸체와 잔해를 고르고 유한한 적분 운동량을 나눈다. 몸체별 누적 속도 변화 상한을 적용하며, 빈 시간이나 상한 초과분을 뒤의 시간·다른 몸체에 다시 배분하지 않는다.

### Arena 선택 규칙

- 중력 선행이 자동 또는 Space 발동 지점에 도달하면 종류와 관계없이 원본 장과 그 장의 미처리 명령을 먼저 소모한다. 대상의 저장 불가나 생성 실패처럼 발동 시도 뒤 실패한 효과도 장을 되돌리지 않는다. 분열은 해제 전에 남은 반경·시간 예산을 회수한다. 발동 전에 대상 제거 등으로 예약 자체가 취소된 경우에만 원본 장을 자기 수명까지 유지한다.
- Arena 전용 Heavy 스탯은 체력600·공격력90·사거리1300이며 기존 전장의 표를 바꾸지 않는다. 새 전장의 초기 Heavy는 남쪽에서 별도 공성 경로를 사용한다. 요청 전개 지점은 실제 점유·사거리·포탄 경로가 막히면 기존 대안 선택 규칙으로 바뀔 수 있으며, 그 좌표에 반드시 정착한다고 보장하지 않는다.

- `SupplyStageOne`에서 `SupplyTuning.Arena.bEnabled`를 켜면 이 절의 예외를 적용한다. 기본값은 꺼짐이며 `Legacy`와 Arena 설정을 끈 `SupplyStageOne`은 기존 규칙을 유지한다. 발사할 때 Arena 설정도 함께 복사하므로 비행 중 설정을 바꾸어도 그 발사의 규칙은 바뀌지 않는다.
- 모듈 폭발과 환경 기폭은 노출된 몸체마다 거리 감쇠를 적용한 충격을 독립적으로 준다. 모듈의 몸체별 속도 변화 상한과 환경 기폭의 방향·상향 비율은 유지한다. 일반 폭발의 실제 형상 차폐는 유지하며, 집결 후행 폭발은 집결 집합에 속한 몸체끼리만 차폐에서 제외한다.
- 냉각 선행은 직격 피해와 직격 충격을 주지 않는다. 착탄점에서 냉기파를 발생시켜 유효한 이동 몸체를 냉각하며 직격과 범위에 함께 포함되어도 같은 몸체에는 한 번 적용한다. 고정 지형과 건축물은 냉기파를 가리지만 이동 몸체는 가리지 않는다. 냉각 후행은 대상이 제거되더라도 마지막 유효 위치에서 발동한다. 분열 자탄은 배분된 냉각 시간과 자탄 범위를 사용한다.
- 중력은 고정 착탄 XY를 바닥에 투영한 장으로 이동 가능한 몸체와 구조 결속 조립체를 수평으로 모은다. 고정 지형과 건축물은 장을 가리고 이동 몸체는 가리지 않으며 실제 물리 충돌과 수직 운동은 유지한다. 여러 장의 명령은 몸체별로 결합하며 고정된 조립체는 이동시키지 않는다.
- 중력 선행의 후행 지연은 Arena 중력 지연을 사용하고 다른 선행 모듈은 기본 지연을 사용한다. Space는 기존처럼 조기 발동한다. 중력→폭발·냉각·추진은 해제 직전 집결 중심과 실제 접촉·구조 결속으로 이어진 몸체 집합을 복사하고 장과 그 장의 미처리 명령을 제거한 뒤 발동한다. 집결 출력은 원래 피격 몸체가 제거되어도 취소하거나 다른 몸체로 대체하지 않는다. 폭발과 냉각은 집결 중심 위의 위치에서, 추진은 기록된 발사 방향으로 집결 몸체에 작용한다. 중력→분열은 남은 장의 반경과 시간을 자탄 장에 전달하고, 분열→중력도 자탄별 장을 만든다.
- 추진 충격을 실제로 받은 몸체에는 강제 이동 표식을 두고, 표식이 있는 몸체가 실제 충돌하면 상대 이동 몸체에도 전달한다. 표식은 몸체 전환에서 승계하고 접지·저속 안정, 제거 또는 전투 종료 때 해제한다. Arena에서는 고정 표면과의 강한 충돌이 이동 몸체에 피해를 줄 수 있다. 바닥이나 벽 윗면처럼 착지 성격인 접촉은 표식이 있을 때만 이 추가 피해를 준다. 일반 착지와 기존 폭약 충돌 기폭 규칙은 유지한다.
- 저장 전하 표현은 반응 컴포넌트가 실제 몸체와 전하의 수명에 묶어 관리한다. 충전 섬광, 저장 중 표시와 실제 접촉 방전을 구별하며 표현은 충돌·내비게이션·피해를 만들지 않는다. 전하가 없어지거나 몸체가 제거되거나 전투가 끝나면 저장 표시를 정리한다.
- 같은 보급 일정에서 `bArenaPressureEnabled`를 켜면 지정 시각마다 지정된 각 진입점에서 실제 Assault를 별도로 생성한다. 이 증원은 보급 잔존 물자 한도와 성공 출발 순번에 포함하지 않는다. 살아 있는 Assault가 설정한 한도에 도달하면 해당 시도를 건너뛴다. 진입점과 바깥쪽 대안에 대해 실제 지면·전장 경계·내비게이션·겹침을 검사하며, 둘 다 막히면 설정한 간격과 횟수만큼 재시도한다. 진입점에는 충돌과 내비게이션에 영향을 주지 않는 바닥 표식을 두고 출발 전 남은 시간을 표시한다. 전투 결과가 확정되면 대기 중인 시도와 예고를 중단한다. 초기 Assault 목록은 비어 있지 않고 같은 월드의 유효한 중복 없는 Assault로 구성한다.
- 보급과 공성의 최소 예고 시간은 재장전, 관찰된 최장 비행, 가능한 가장 긴 후행 지연과 입력 여유를 포함한다. Arena의 중력 지연도 이 최장 지연에 포함한다.

### 전하·전도·피해 출처

- 전격은 유한 전하를 저장하며 충전 자체로 피해·기절·상시 방전을 만들지 않는다. 저장 상한의 남은 양만 새 패킷에서 받아들이고 넘친 입력만 소산한다. 기존 패킷을 밀어내거나 다시 쓰지 않으며 자연 충전·감쇠도 없다. 체력 사망은 잔여량을 재설정하지 않고 물리적 제거는 남은 전하를 한 번 폐기한다.
- 패킷은 고유 식별값, 분할 계보, 원본 생성 순서, 현재 몸체에서의 활성 순서, 공격자 식별값·약한 참조, 진영, 발사 식별값과 자원 출처를 가진다. 공격자 제거가 저장된 진영·출처를 지우지 않는다. 분할 패킷은 서로 다른 식별값을 받되 계보와 생성 순서를 보존한다.
- 실제 새 접촉만 방전 계기다. 양쪽 충돌 알림은 같은 접촉을 한 번만 예약하고, 연속 접촉은 실제 몸체 사이의 3cm 접촉 허용 간격을 벗어난 뒤 재접촉해야 새 사건이 된다. 충전 활성 순서보다 앞선 접촉은 나중에 처리되더라도 소급 방전하지 않는다. 지면·벽·표현용 메시를 전기 피해 대상이나 전도 경로로 만들지 않는다. 다만 폭약의 강한 지면·벽 충돌은 기존 물리 충돌 기폭 규칙을 따르며 지면·벽에 체력 피해를 주지는 않는다.
- 철구·철판·수송 차대·축전지와 공성 Heavy의 금속 몸체는 저장·중계할 수 있다. 살아 있는 Heavy는 중계 몸체이면서 피해 종점이다. 사망한 Heavy의 남은 금속 몸체는 중계만 하고 피해 종점으로 쓰지 않는다. 다른 살아 있는 병력과 비전도 폭약통, 성·핵심 거점은 피해 종점이며 다른 대상까지 중계하지 않는다. 병력은 저장도 가능하지만 폭약통·성·핵심 거점은 저장하지 않는다. 얼음·포가는 이전 몸체의 저장·중계 정책을 보존한다. 그 밖의 금속 중계 몸체와 체력상 죽은 몸체는 피해 배분 종점에 넣지 않는다.
- 전도망은 실제 연속 금속 접촉과 선언된 금속 결속·접착만 사용한다. 거리만으로 전기선을 만들거나 벽을 건너뛰지 않는다. 각 FIFO 접촉에서 당시의 전도망·종점을 고정하고 사건 예산 안에서 오래된 패킷부터 소비한다. 같은 생성 순서에서는 패킷 식별값과 운반 몸체 식별값으로 순서를 정한다. 패킷의 운반 몸체를 제외한 고유 종점에 균등 배분하고 같은 패킷이 같은 사건에서 같은 종점을 반복 타격하지 않는다. 종점이 없으면 소비하지 않는다.
- 접촉의 속도·질량·몸체와 전하 배분을 피해 전에 고정한 뒤 기계적 접촉 피해와 전격 피해를 순서대로 처리한다. 장갑·거부된 피해·초과 피해로 소모된 전하는 반환하지 않는다. 후속 기폭도 공통 FIFO와 프레임 말미 판정 전에 처리하고, 결과가 확정되면 신규 예약·연쇄 피해를 받지 않는다.
- 포탄·모듈 피해, 플레이어가 생성한 철구의 충돌과 플레이어 전격으로 저장한 전하는 핵심 거점의 직접 공격 장갑 감소를 적용한다. 이후 발에서 재사용해도 플레이어 자원 출처를 유지한다. 맵·수송 소재의 충돌, 폭약·약점의 환경 기폭과 축전지 전하는 환경 출처를 유지한다. 혼합 전하는 패킷별로 계산하고 방전의 공격 원점은 실제 접촉점으로 기록한다.

### 생성·분열·접착·냉각과 사망

- 철구 모듈은 기존 대상을 변환하지 않고 같은 금속구 규칙의 새 몸체를 만든다. 실제 형상·바닥·진입 여유를 검사한 지점에서 발사 방향의 유한 생성 충격으로 출발하며 철구 선행의 후행 효과는 이 생성 몸체를 따른다. 회전한 몸체의 후행 효과는 실제 접점과 회전된 법선을 따른다. 생성 위치는 실제 바닥·진입 여유·충돌 검사를 따르며 입사 방향과 표면 법선의 각도만으로 거부하지 않는다. 생성 실패는 대상 소멸과 다르므로 원래 대상이나 빈 착탄점으로 후행 효과를 대체하지 않고 예약 전체를 취소한다. 생성 총질량·몸체 수 상한을 적용하고 초과 시 새 생성을 거부한다. 비행 중에는 생성 자원을 예약하지 않아 미명중·배치 실패가 용량을 영구 점유하지 않는다.
- 조준한 플레이어 생성 물체는 G로 회수할 수 있다. 회수는 해당 물체의 전하·결속·예약 몸체 효과를 취소하고 기폭 없이 제거한다. 사망 전환으로 이어진 생성 물체도 같은 출처·예산을 잇는다. 맵·수송 물체는 회수하지 않으며, 사용 중인 몸체에 임의 시간 만료를 걸지 않는다.
- 분열 선행은 원본 후행 예약 없이 배분한 모듈을 세 자탄에 전달한다. 분열 후행도 선행 효과의 성질을 전달한다. 직접 피해·충격·전하·생성 질량·접착 슬롯과 강도·냉각 시간은 원본과 자탄의 유한 예산으로 나누며 자탄은 재분열하거나 개별 Space 대상이 되지 않는다. 전하나 중력의 미사용 예산이 없는 자탄은 해당 전격·중력 효과와 그 효과 표시를 생략한다. 자탄은 실제 첫 차단 몸체에서 반응하므로 같은 몸체에 다시 막힐 수 있다.
- 전격→분열은 그 발사가 만든 패킷의 실제 잔여량만 자탄으로 옮기며 다른 전하나 이미 쓴 양을 복제하지 않는다. Arena 설정을 끈 규칙의 중력→분열은 기존 장을 끝내고 미사용 운동량만 전달한다. 철구→분열은 생성된 큰 몸체 하나를 실제 작은 몸체 셋으로 바꾼다. 정해진 대칭 배치 하나에서 세 몸체·자세·저장 용량·이전 상태가 준비된 뒤에만 원본을 제거하며 질량·운동량·잔여 전하·체력·유효 결속의 합을 보존한다. 그 배치가 막히면 다른 회전을 탐색하지 않고 원본을 그대로 두며 자식만 취소한다.
- 접착은 맞은 이동 가능 몸체의 실제 접촉을 유한 슬롯·강도로 결속한다. 접촉 없는 근접 흡착과 지면 고정은 하지 않는다. 별도 몸체를 잠긴 native 물리 constraint로 연결하고 결속 동안 그 쌍의 솔버 충돌을 끈다. 각 물리 스텝 뒤 constraint의 선형 충격을 배분한 강도가 반영된 한 스텝 충격 한도와 비교하며 시간 간격으로 환산하지 않는다. 한도를 넘거나 부위가 제거·회수되면 끊어지고 소비한 슬롯은 복구하지 않는다. 적재 결속처럼 다른 소유자의 구조 접촉을 덮거나 해제하지 않는다.
- 살아 있는 Character의 접착·냉각은 기존 캡슐의 강체 제어로 전환하고 이동·공격·AI 상태를 보관한다. 냉각은 저마찰·취성을 적용하지만 질량·전도성을 자동 변경하거나 다른 몸체에 전염시키지 않는다. 살아 있는 대상은 남은 냉각 시간과 새 입력 중 큰 값을 쓰며, 제어 사유가 모두 끝난 뒤 접지·자세·선속도·각속도가 안정되어야 보관한 행동을 복원한다. 전투 종료나 사망·공성 제어를 되돌리지 않는다.
- 철구는 완전 파쇄되면 제거되고 폭약통·폭발성 Carrier는 기존 페이로드를 한 번 기폭한 뒤 제거된다. 냉각이 이 파괴 정책을 새 얼음 보상으로 바꾸지 않는다. 비폭발성 Assault·Heavy가 냉각된 채 사망하면 실험 전용 얼음 몸체 하나로 질량·운동·잔여 전하와 식별값을 이전한다. 얼음은 캡처한 실제 형상을 유지한다. 냉각하지 않은 일반 병력은 제거되고 Heavy는 공격 없는 포가를 남긴다. 새 상자형이 기존 결속을 끊거나 주변 몸체와 새로 겹치지 않을 때만 그 형상을 선택하며, 그 밖에는 캡처 형상을 유지한다. 어느 경우에도 질량·자세·선운동량·각운동량을 이어받는다. 약점 기폭·분열 해금·소모된 페이로드를 전환으로 다시 지급하지 않는다.
- 철판·차대·축전지처럼 사망 후 몸체를 유지하는 기물은 같은 Actor·primitive를 유지한다. 철판은 지지를 풀고, 차대는 기능을 영구 중단하고 화물을 해제하며, 축전지는 남은 전하를 가진 셀로 남는다. 이 기물의 냉각 사망은 같은 몸체를 영구 냉각 상태로 유지한다. 냉각 사망체는 시간 경과로 해동·부활하지 않으며 강한 실제 충돌의 파쇄나 물리적 제거로 사라진다. 새 체력 풀은 없다.

### 수송·보급·공성·내비게이션

- `ALSShellTransport`는 실제 기존 화물을 차대 위에 적재하고 개별 constraint로 고정한다. 몸체 식별값·결속 접촉과 지지 형상이 준비되기 전에는 시뮬레이션을 시작하지 않는다. 금속 적재 연결은 전도하고 폭약통 적재 연결은 절연한다. 연결된 실제 총질량을 한 번만 사용하며 자기 구동을 외력으로 오인하지 않는다.
- 하역·차대 사망·제거 때 결속과 절연을 한 번 해제하고 원래 화물의 월드 자세·속도·체력·전하를 유지한다. 보급 일정에 속한 차대는 실제 퇴장 경로의 첫 방향으로 물리 힘과 토크로 정렬하고 위치·선속도·방향·각속도가 안정된 뒤 하역한다. 하역 전 정렬과 퇴장은 같은 경유점을 사용하며 자세나 속도를 강제로 덮어쓰지 않는다. 배송 뒤 랙 유지가 지정된 화물은 차대에 계속 결속해 두고, 소모 화물은 실제 하역한다. 랙에 남은 화물이 있으면 빈차 퇴장을 막으며 해당 화물 또는 차대의 공통 사망 때 결속을 해제한다. 결속 중에는 일시적인 joint 늘어남에도 선언한 구조 접촉을 유지한다. 해제만으로 새 접촉·방전을 만들지 않으며, 해제 뒤 실제 분리·재접촉은 정상 새 사건이다. 차대 사망은 같은 Actor·root를 유지하고 주행·AI·하역 기능을 영구 중단하지만 남은 물리 속도를 지우지 않는다.
- `ALSShellSupplySchedule`은 전멸 조건 없이 서로 다른 두 경로와 고정 출발 일정을 실행한다. 충전 화물과 병력 보충은 예정 회차가 아니라 **성공한 출발 순번**을 따른다. B 경로의 두 번째 성공 출발에 충전 화물을 사용하므로 자리 검사에 실패한 회차가 충전 변주를 소모하지 않는다. 완성 배치에서는 B 경로의 판만 배송 뒤 랙에 남기고, 나머지 소모 화물은 실제 하역한다. 예고에는 재장전·최장 비행·효과 지연·입력 여유를 포함하며 현재 재장전 상태에 맞춰 일정을 바꾸지 않는다.
- 하역 후보와 경로의 실제 적재 형상을 검사하고 점유·잔존 물자 한도에 걸리면 해당 회차를 표시하고 건너뛴다. 출발 예고도 실제 출발과 같은 경로 검사로 현재의 점유를 반영하며, 경로가 막힌 상태를 정상 출발 예정으로 표시하지 않는다. 보충 병력은 실제 지면·경계·겹침 검사 실패 때 제한된 재시도만 하며, 같은 실패 상태를 반복해 대기 알림을 쌓지 않는다. 출발 경고는 일시 대기·배송 알림보다 우선한다. 살아 있는 빈차는 랙이 비워진 뒤 검증한 퇴장 경유점과 전장 바깥까지 이어진 바닥을 따라 장외로 이동해 제거된다. 차대·화물·보충 병력 중 남은 자원은 같은 보급분으로 계속 집계하고, 이미 배달한 물체를 만료·복제·순간이동해 자리를 만들지 않는다.
- Heavy의 `ULSShellSiegeController`는 기존 공통 공격·약점과 함께 이동·전개·장전 예고·발사·재장전·외력 회복을 제어한다. 기준 배치점이 막히면 실제 형상·점유 예약·사거리·이동 경로를 검사한 대체 배치 후보를 순서대로 확인한다. 단계 제어가 활성화되면 일반 적 행동과 이중 구동하지 않는다. 이동·배치 이탈이나 외부 제어로 발사를 중단하고 정상 조건을 회복한 뒤 다시 진행한다.
- `ULSShellNavigationBodyComponent`는 실제 primitive를 처음에는 nav에서 제외하고, 속도·각속도와 대기 창 안의 실제 변위가 정착 조건을 유지하면 native 형상으로 등록하며 wake·이동·회전·충돌 제거 때 해제한다. 정착 창의 이동 원점과 이미 등록한 형상의 이동 기준은 구분한다. 구의 회전과 캡슐의 길이 축 스핀은 형상을 바꾸지 않으므로 회전만으로 등록을 해제하거나 정착을 거부하지 않는다. 중심 이동과 캡슐의 기울기, 상자의 회전은 계속 검사한다. 정착 창을 통과하는 느린 이동체도 등록 위치에서 이동 허용 거리를 넘으면 해제되며, 수면 상태에서만 등록하는 정책은 아니다. 표현 메시와 별도 AABB 형상을 장애물로 등록하지 않는다. `ULSShellObstacleResponseComponent`는 실제 요청 경로의 구간을 검사하며 살아 있는 명시적 차단물은 공통 공격, 잔해는 구조적으로 연결된 질량·접지 마찰과 실제 옆 공간을 검사한 제한된 힘으로 대응한다. 실패하면 실제 대안 경로를 조회하고 기존 적 행동의 요청 소유권으로 재탐색하며, 길이 없다는 실패를 성공으로 숨기지 않는다.
- 강체 전체가 전장 확장 경계를 벗어나거나 낙하 제거 조건에 도달하면 전하·결속·몸체 대상을 정리하고 추가 기폭 없이 제거한다. 경계 안의 사용 중인 몸체에는 자동 수명 만료가 없다.

### 입력·표현·저작

- `ULSShellSupplyExperimentWidget`과 개선 WBP는 작은 체력·조합·재장전 표시, 두 슬롯과 공용 모듈 선택지, F 조합판, 조건부 Space 위치·화면 밖 방향, 오류·결과·재시작을 제공한다. 컨트롤러는 `UUserWidget` 파생을 받으므로 기존 WBP도 같은 생성 경로를 유지한다. Space는 최신 유효 원본의 후행 효과 하나만 제어한다.
- 저장 전하·접착 접점·냉각 표면·공성 준비와 확정된 방전·충돌·기폭을 구별해 표시한다. HUD의 사건 안내는 실제 보급 일정 상태와 가장 임박한 공성 예고를 반영한다. 연출은 확정된 값만 복사하며 피해·충격·연쇄 시점을 늦추지 않는다. 공통 피해 호출 중의 원인만 기폭 예약에 복사하고 이전 비치명 피해의 원인을 다음 피해에 남기지 않는다.
- `ULSShellSupplyEditorLibrary`는 개선 위젯·바닥의 채널·물리 재질을 저작·검증한다. 조합판은 공용 모듈 선택과 현재 두 효과의 짧은 작용·발동 설명을 보여준다. 기존 유효 배치를 보존하고 잘못된 에셋을 덮어쓰지 않으며 저장은 호출자가 담당한다. 개선 저작 스크립트의 단계 전진은 가산 방식이고 기존 수동 변형·수치를 보존한다. 단계 소유 필드가 예상과 다르면 쓰기 전에 중단하며, 같거나 낮은 단계 요청은 되돌리지 않는다. 이미 Complete인 맵의 배치 수정은 별도 명시 옵션만 허용하고, 예상된 이전/수정 위치·경로·랙 설정이 하나라도 다르면 변경하지 않는다.

### 기존 전장 규칙

- `/Game/Landship/ShellExperiment/Maps/L_ShellExperiment`는 실제 `ALSCastle` 파생 성에서 포탄을 발사하고 효과 순서와 연쇄 기폭을 비교하는 별도 전장이다. 기존 전장의 게임플레이 배치와 조작을 바꾸지 않는다. 저작과 실행은 [포탄 조합 실험 절차](../../../docs/procedures/shell-experiment.md)를 따른다.
- `ALSShellExperimentGameMode`는 기존 `ALSGameMode`의 전투 종료 판정을 사용하며 실험의 시작 조건을 검사한다. `ALSShellExperimentController`는 이 맵에서 조준·사격·조합 입력을 담당한다. `ULSShellExperimentWidget`은 해당 상태와 재시작·순서 변경 동작을 제공하고, 배치와 디자인은 실험 전용 위젯 블루프린트가 담당한다.
- `ALSShellExperimentCoordinator`는 명시적으로 연결한 PlayerCastle과 CoreOutpost를 사용한다. 발사 시점의 조합을 보존하고, 실험 포탄·모듈·물체의 피해 및 연쇄 반응을 공통 체력 처리로 전달한다. 전투 결과가 확정되면 새 실험 발사·예약·게임플레이 연쇄 피해를 받지 않는다. 기존 공통 판정의 MutualDestruction은 실험 화면에서 승리로 표시한다.
  - 반응 대기열은 `OnWorldPostActorTick`에서 소진한다. 새 액터의 틱까지 끝난 뒤이며 공통 승패 수집의 `OnWorldTickEnd`보다 앞선다. 이 처리 중 생성한 자탄은 다음 프레임부터 비행하고, 명중한 프레임의 피해·후속 반응은 그 프레임의 판정 전에 끝낸다.
- `ALSShellExperimentEnemy`는 공통 `FLSUnitStatRow`를 담은 StatsTable과 StatsRowName을 사용한다. 행 이름을 비우면 EnemyKind와 같은 이름의 행을 읽는다. 공통 적 행동 컴포넌트로 요새를 향해 이동하고 공격하며 실험의 강제 이동 반응을 추가한다.
- Heavy는 본체와 별도 `ALSShellWeakPoint`를 사용한다. 약점은 조준·탄체만 차단하고 본체 이동과 자기 사격을 막지 않는다. 같은 폭발의 대상 목록은 약점부터 처리한다. 약점 사망은 대형 기폭을 예약하고 본체를 격파하며, 본체만 사망하면 약점을 기폭 없이 제거한다. 두 경로 모두 분열을 한 번 해금한다.
- Legacy의 분열 선행은 자탄 세 발에 후행 모듈을 한 번씩 상속하고 원본 후행 예약은 만들지 않는다. Legacy의 분열 후행은 직접 명중만 하는 자탄을 만든다. 자탄은 실제 첫 차단 몸체에서 소멸하고, 명중 없이 수명·거리·경계에 도달하면 효과를 실행하지 않는다. 전투 몸체 정면에서는 세 발이 같은 몸체에 다시 맞을 수 있다.
- F를 눌러 조합을 열고, 다시 F를 누르면 선택을 확정한다. 조합 중에는 슬롯 버튼과 R로 편집한다. 창의 포커스를 잃거나 컨트롤러·위젯이 해제되면 미확정 선택을 버린다. 두 종료 경로 모두 시간 배율을 1로 복원한다.
- Legacy에서 사건을 켠 전장은 설정한 시간에 한 번 후보를 검사하고 유효한 사건을 미리 예고한다. 수송대는 두 진입점의 몸체 여유·내비게이션 경로를 모두 확인한다. 공세는 예고한 기존 Heavy에만 적용한다. 예고 후 조건이 사라지면 취소하고 다시 시도하지 않는다.
- `ALSShellExplosive`는 공통 장애물의 체력·피격 몸체를 사용한다. `ULSShellReactiveComponent`의 기폭 요청은 한 번만 접수하고 기폭 수치와 공격자 정보를 복사해 조정자의 반응 대기열로 넘긴다. 피해와 충격은 별개의 값이다.
  - 폭발 모듈은 생존한 이동 객체를 확실히 밀어내도록 바깥쪽·위쪽 충격에 조정 가능한 최소값을 둔다. 자탄은 효과 배율에 맞춰 줄이며 피해 감쇠와 반경은 유지한다. 환경 기폭은 기존 선형 충격 감쇠를 사용한다. 처음 강제 이동으로 넘어갈 때 AI 보행만 멈추고, 이미 중력·충격으로 얻은 속도에는 새 충격을 합산한다. 이동 저항과 실제 몸체 충돌은 계속 적용한다.
- `ALSShellExplosive::bAuxiliaryFacility`는 고정 폭발물과 보조 시설의 외형·표시를 구분한다. 이 플래그 자체는 체력이나 피격 몸체를 바꾸지 않는다.
- `ULSShellExperimentEditorLibrary::BuildWidgetAsset`은 에디터에서 실험 전용 위젯 블루프린트를 저작해 반환한다. 비어 있는 에셋을 채우고 유효한 기존 배치는 보존하며, 기존 배치가 잘못되었거나 런타임에서 호출하면 null을 반환한다. 호출자가 반환된 에셋을 저장한다.
- `ULSShellExperimentEditorLibrary::UpgradeFeedbackWidgetAsset`은 기존 위젯 배치를 보존하면서 선택 항목인 `ReactionText`와 글자 그림자를 추가한다. 위젯은 반응 설명을 표시하며 실제 피해·충돌을 새로 만들지 않는다. 호출자가 반환된 에셋을 저장한다.
- `UpgradeP1WidgetAsset`은 기존 위젯에 슬롯별 모듈 버튼과 분열 해금 표시를 추가한다. `--populate-p1`은 기존 액터를 보존하면서 Legacy P1 구성에서 부족한 병력·폭발물·시설을 추가한다. 기존 대상의 이름·병종이 맞지 않으면 중단한다.
- 실험 전용 `M_ShellEffect`와 `M_ShellRing`은 Tint·Opacity 파라미터를 제공한다. 전자는 채워진 섬광·탄도 표시, 후자는 Fresnel 불투명도를 적용한 링·충격파 표시에 쓴다.

## 동작 조건

- 유효한 BattlefieldSetup, BattlefieldSettings, ShellExperimentCoordinator를 각각 하나만 배치한다. 세 액터의 성·핵심 참조는 같은 월드에 있어야 한다. 성은 실제 게임의 `ALSCastle` 파생이며, 핵심 거점은 `ALSOutpost` 파생으로 사망 후에도 유지해야 한다.
- 실험 시작 시 Combat Developer Settings의 오폭 허용과 자기 피해 허용이 모두 켜져 있어야 한다. 빠진 조건은 구성 오류로 표시하며 전투 입력과 실험 적의 전투 행동을 시작하지 않는다. 실험 모드는 프로젝트 공통 설정을 자동 변경하지 않는다.
- 두 피해 정책 플래그는 해당 PIE 세션 동안 유지해야 한다. PIE 도중 설정 변경은 지원하지 않으므로 종료 후 다시 시작해 시작 조건을 검사한다.
- 실험 전용 GameMode 밖에서 배치한 실험 적과 폭발물은 전투를 시작하지 않는다. 시작 조건이 잘못된 경우 적의 행동 종료는 이 폴더가 요청하며, 착지 후에도 다시 켜지 않는다.
- 이 전장은 `ULSBattlefieldNavigationSystem`의 맵별 에이전트 설정과 실제 NavMeshBoundsVolume 브러시를 사용한다. 실물의 안개 은폐는 끄고 공개 핵심 위치 플래그는 핵심 거점에만 켠다.
- 기본 성·병력·거점의 공유 DataTable과 무장을 고치지 않는다. 실험 적과 핵심의 DataTable 원본은 `Data/ShellExperiment/`에 둔다. 성은 공유 CastleStats의 BattlefieldPrototype 행을 사용한다.
- 기존 Legacy 저작 스크립트의 기본 배치는 일반 적 하나와 작은 폭발물 연쇄만 둔다. 새 맵은 `LevelEditorSubsystem.new_level_from_template`로 만들며 일반 에셋 복제 경로로 UWorld를 복제하지 않는다. 기본 실행에서는 이미 있는 실험 맵을 보존한다. Legacy의 `--resume-authoring`을 명시한 실행만 부분 저작된 실험 대상 맵의 배치를 다시 구성하고 실험 전용 에셋의 지정 기본값을 다시 적용한다. 정상 실행 뒤에도 에디터를 유지한다. 실제 플레이에서 첫 경로를 확인한 뒤 전장 규모를 넓힌다.
- Legacy의 `--update-feedback`은 배치를 다시 만들지 않고 실험 대상 맵의 보조 시설 표시와 실험 전용 링·소리·위젯만 갱신한다. 소리는 기존 발사·폭발·명중 에셋만 덮어 가져온다. 이 인수와 `--resume-authoring`은 함께 쓰지 않는다.

## 하지 않는 일

- 이 폴더는 기존 맵의 성 이동·병력 명령·Q/W/E 무장 조작을 교체하지 않는다. 기존 조작은 `Controls`와 `Castle`이 담당한다.
- 진영·체력 차감·사망·거점 함락·전투 결과의 원본을 새로 만들지 않는다. 각각 공통 `Combat`, `Enemies`, `Match` 구현을 사용한다.
- 기존 지역 출격 조정자나 V0 배치 프리셋을 실험에 가져오지 않는다. 기본 저작의 작은 배치와 `--populate-p1`의 전체 배치를 구분한다.
- 관통, 동적 건물 붕괴, 다량의 물리 파편은 제공하지 않는다.

## 공용 테스트 맵

해당 없음. 실험 플레이 전장은 위 경로의 기능 맵이며, 저작에 필요한 스크립트와 확인 순서는 [포탄 조합 실험 절차](../../../docs/procedures/shell-experiment.md)에 둔다.
